# Директива первого delivery-цикла 2026-09-07

## Статус источника

Источник: прямые сообщения владельца продукта в текущем продолжении разговора о EXIM Super App от 2026-09-07. Этот документ фиксирует только относящиеся к передаче разработки указания и отделяет их от решений task curator.

## Прямые указания владельца

> «Дай ему тзшку получается.»

> «Сделай все по красоте и правильно. Как сениор программист. Без рофла щас говорю! Нужно все четко в мейн пренести. Делай.»

> «Первое задание было написано для клода в репозиторий? ... все ли готово чтобы он сразу же начал работу? Добавь место где он тебе отчетность будет подробную давать в той же репозиторий чтобы ты мог сразу читать и выдавать следующию задачу. Кароче делаем бесконечный цикл до идеального суперапа.»

## Что этим подтверждено

- в Product OS `main` должно находиться первое крупное задание для Claude Code;
- после предоставления точного доступа Claude должен начинать без ожидания новой порции мелких указаний;
- подробная отчётность исполнителя должна возвращаться в этот же Product OS;
- после проверки отчёта формируется следующая задача, и цикл повторяется;
- README и стартовая инструкция должны соответствовать текущему процессу, без активной передачи через Cursor.

## Формализация task curator

В качестве первого пакета выбран уже подготовленный Product OS **Foundation Gate**: это ближайший pre-launch пакет, который закрывает выявленные live-аудитом базовые разрывы до Exchange. Детальный scope, AC, запреты само-приёмки, immutable reports и безопасный preflight — формализация task curator по поручению сделать передачу «как сениор программист», а не утверждение, будто владелец дословно перечислил каждый технический пункт.

Task-level Gate defaults действуют только для revision 1 и стартового tenant `exim.kz`. Они не становятся универсальными продуктовыми решениями и не закрывают `TBD`/`OQ-*`.

## Что не подтверждено этой директивой

- точный application repository, base branch и исходный SHA;
- стек, auth provider и deployment model рабочего приложения;
- production deploy;
- автоматическая приёмка работы Claude или интегратора;
- Exchange scope внутри первого Foundation Gate.
