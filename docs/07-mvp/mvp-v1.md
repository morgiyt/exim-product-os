# MVP v1

## Цель

Провести одну реальную перевозку от запроса до поэтапного закрытия и дать клиенту достоверный ручной tracking без внутренних данных EXIM.

## Сквозной сценарий

```text
Менеджер создаёт клиента
→ создаёт или принимает запрос на расчёт
→ передаёт логисту
→ получает цену и комментарий (входит / не входит)
→ устанавливает итоговую цену и маржу
→ при низкой марже согласовывает с руководителем продаж
→ отправляет коммерческое предложение
→ фиксирует годовой договор и заявку к договору
→ вручную создаёт перевозку
→ ответственный логист = автор выбранного расчёта
→ создаются рейсы
→ менеджер публикует статусы и плановую дату
→ бухгалтер фиксирует оплату
→ поэтапное закрытие: доставка → АВР → оплата → документы
```

## Обязательно

- авторизация и роли, включая бухгалтера и руководителя продаж;
- клиентская компания, несколько пользователей, основной менеджер;
- временная передача клиента с обязательной заметкой;
- раздельные сущности: лид, запрос, расчёт, предложение, сделка, годовой договор, заявка к договору, перевозка, рейс;
- обязательные поля запроса на расчёт;
- версии расчётов и история изменений цены;
- разделение себестоимости / маржи и итоговой цены для клиента;
- перевозка после подписания договора/заявки;
- история плановых дат с причиной;
- внутреннее и клиентское событие;
- клиентская карточка без перевозчика, водителя и контактов;
- документы;
- чат клиент — менеджер;
- dashboard руководителя продаж;
- оплата бухгалтером;
- поэтапное закрытие перевозки;
- аудит критических действий.

## Не входит

GPS, WhatsApp, Telegram, email-автоматизация, встроенная оплата, ЭЦП, полная замена Bitrix, marketplace, каталог инфраструктуры, кабинет сторонней логистической компании, утверждённый числовой SLA расчёта.

## Гипотезы MVP

- приглашение клиента в приложение после расчёта или согласования цены (H-001);
- внутренний контроль очереди расчётов без жёсткого SLA (H-002).
