# Known Bugs и ограничения аудита

## Критические ограничения

### Нет подтверждённых тестовых аккаунтов ролей

Без аккаунтов клиента, менеджера, логиста и администратора невозможно проверить защищённую часть приложения: dashboards, списки, карточки, workflow-переходы, документы, чат, уведомления и сохранение данных.

Это ограничение аудита, а не доказательство отсутствия функций.

### Репозиторий приложения недоступен

Исходный код `exim-app` не был доступен. Поэтому не проверялись:

- frontend/backend архитектура;
- база данных;
- auth policies;
- API;
- hardcoded статусы;
- mock-данные;
- Vercel-конфигурация;
- переменные окружения.

## UX Findings

Эти наблюдения зафиксированы по публичным экранам и скриншотам. Они не являются подтверждёнными backend-багами.

1. Desktop-страницы `login` и `verify` занимают только узкую левую область и оставляют большую пустую область экрана.
2. `register` использует другой полноценный desktop-layout, из-за чего auth-раздел выглядит несогласованно.
3. На `login` поле email слишком узкое: placeholder визуально обрезается.
4. Тестовую регистрацию нельзя завершить без доступа к почтовому ящику.
5. Нет предоставленных тестовых аккаунтов четырёх ролей.

## Наблюдаемые технические факты

- `/app` и проверенные `/app/*` маршруты без сессии возвращают HTTP 307 на `/login`.
- Тестовая регистрация приводит на `/verify`.
- Login unconfirmed user возвращает на `/verify`.
- Публичные страницы не показали ошибок приложения в Browser console logs.
