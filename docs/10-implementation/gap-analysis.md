# Gap Analysis

## Проверенная область

Проверена только публичная часть auth flow:

- вход;
- регистрация;
- восстановление пароля как интерфейс;
- подтверждение email как интерфейс;
- redirect защищённых маршрутов на `/login` без сессии;
- мобильное отображение login на 390px.

## Подтверждённые соответствия Product OS

- Приложение имеет защищённую зону, что соответствует ролевой модели Product OS: [Роли](../02-process/roles), [Права и видимость](../03-product-map/permissions).
- Регистрация и email verification частично соответствуют гипотезе о моменте приглашения клиента: [H-001/OQ-023](../09-decisions/open-questions).
- Публичная часть не раскрывает внутренние данные EXIM, что соответствует правилу клиентского слоя: [Два слоя данных](../03-product-map/data-layers).

## Не проверено

Невозможно сделать вывод о соответствии следующим требованиям без role accounts и исходного кода приложения:

- клиентский кабинет и создание запроса;
- менеджерский dashboard, клиентская карточка и карточка запроса;
- передача запроса логисту;
- расчёт ставки и передача ставки менеджеру;
- формирование клиентской цены;
- создание перевозки и рейсов;
- внутренние tracking-события;
- публикация клиентского статуса менеджером;
- документы;
- чат;
- уведомления;
- сохранение данных после reload;
- workflow templates, versions, stages, transitions, instances и history;
- отсутствие hardcoded статусов;
- отсутствие mock-данных в защищённой части.

## Расхождения и риски

| Область | Наблюдение | Риск | Связь с Product OS |
|---|---|---|---|
| Auth UX | Login/verify используют узкий desktop layout | Публичная часть выглядит неустойчиво для демонстрации | [Product Foundation](../01-foundation/product-foundation) |
| Auth UX | Register выглядит иначе, чем login/verify | Несогласованность первого впечатления клиента | [Product Foundation](../01-foundation/product-foundation) |
| QA доступ | Нет role accounts | Невозможно сертифицировать MVP-функции | [MVP v1](../07-mvp/mvp-v1) |
| Workflow | Protected workflow не проверен | Нельзя подтвердить D-066…D-072 | [Configurable Workflow Foundation](../01-foundation/configurable-workflow-foundation) |

## Что безопасно показывать руководству

- Публичные auth-экраны с оговоркой о UX findings.
- Факт redirect защищённой зоны на login без сессии.
- Прозрачный статус: полный аудит защищённой части ожидает тестовые аккаунты.

## Что пока нельзя показывать как готовое

- Role dashboards.
- Quote-to-shipment workflow.
- Tracking publication flow.
- Documents, chat, notifications.
- Соответствие Configurable Workflow Foundation.
- Соответствие Product OS в защищённой части.

## Следующие 5 задач

1. Выдать подтверждённые тестовые аккаунты клиента, менеджера, логиста и администратора.
2. Предоставить репозиторий приложения для source audit.
3. Подготовить seed dataset: клиент, запрос, ставка, перевозка, рейс, документ, событие.
4. Повторить Browser-аудит защищённой части с проверкой сохранения после reload.
5. Сравнить workflow-реализацию с [REQ-003](../06-requirements/REQ-003-configurable-workflow-mvp).
