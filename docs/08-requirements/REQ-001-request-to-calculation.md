# REQ-001 — Запрос и передача на расчёт

## Цель

Создать контролируемый процесс от данных клиента до расчёта логиста.

## Сценарий

1. Менеджер создаёт запрос либо клиент отправляет форму.
2. Запрос назначается персональному менеджеру.
3. Менеджер проверяет данные.
4. При нехватке данных запрашивает уточнение.
5. Менеджер назначает логиста и дедлайн.
6. Логист получает задачу.
7. Логист заполняет структурированный расчёт.
8. Менеджер получает уведомление.
9. Менеджер добавляет маржу.
10. Формируется итоговое предложение.

## Правила

- без клиента запрос не создаётся;
- клиент не видит себестоимость;
- логист не публикует цену клиенту;
- дедлайн обязателен;
- перенос срока сохраняется в истории;
- расчёт нельзя бесследно перезаписать;
- альтернативные расчёты хранятся отдельно.

## Критерии приёмки

- менеджер видит новые запросы;
- логист видит назначенные расчёты;
- система показывает дедлайн и просрочку;
- расчёт сохраняется после перезагрузки;
- итоговая цена и себестоимость разделены;
- клиентский API не возвращает себестоимость;
- история статусов доступна администратору.
