# REQ-008 — Поиск, отклики и выбор исполнителя

## Статус и цель

**Статус:** draft для Launch MVP.<br>
**Цель:** провести участника от поиска объявления до выбора другой стороны без участия платформы в самой сделке.

## Предлагаемый основной сценарий

Сценарий ниже — рабочий draft. Response model, actor выбора и момент контактов утверждаются только после OQ-040/OQ-043.

1. Пользователь выбирает поиск грузов или транспорта.
2. Применяет маршрут, даты, вид транспорта и применимые параметры.
3. Открывает карточку.
4. Отправляет отклик/предложение по разрешённому capability и entitlement.
5. Владелец просматривает и принимает, отклоняет или оставляет ответ без выбора.
6. В предлагаемой модели принятие создаёт `ExecutorSelection`; открытие контактов выполняется только по будущему утверждённому правилу.
7. Участники договариваются между собой.

## Правила

- поиск возвращает только видимые active listings;
- участник видит только свои отклики и отклики к своим объявлениям;
- нельзя откликаться на своё объявление;
- accepted response не создаёт договор, платёж или гарантию платформы;
- история отклика не удаляется бесследно;
- точный ranking, поля предложения и момент контактов — `TBD`.

## Критерии приёмки

- поиск работает по основным фильтрам;
- два разных участника проходят сценарий отклика и выбора;
- чужие отклики недоступны;
- лимит/entitlement проверяется сервером;
- если открытие контактов входит в утверждённый flow, оно фиксируется;
- закрытое объявление и, если moderation утверждена, заблокированное объявление не принимает новый отклик;
- UI явно сообщает, что дальнейшая сделка заключается между участниками.
