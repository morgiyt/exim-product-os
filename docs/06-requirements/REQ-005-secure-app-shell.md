# REQ-005 — Безопасный и стабильный app shell

## Статус и цель

**Статус:** ready for implementation в Foundation Gate.<br>
**Цель:** сделать существующее приложение надёжной рабочей основой до расширения Exchange.

## Обязательный объём

1. Серверные права клиента, менеджера, логиста и tenant admin. Platform admin в Foundation Gate не требуется.
2. Согласованные данные для dashboard, inbox, workflow и аналитики: одинаковый scope даёт одинаковый результат, разные scopes явно подписаны.
3. Рабочий поиск по доступным объектам.
4. Стабильные прямые ссылки, Reload, Back и Forward.
5. Мобильные экраны 360, 375 и 390 px без overflow всей страницы.
6. Отдельные loading, empty, error, forbidden states и действие «Повторить».
7. Корректная auth callback и recovery UX.
8. Отсутствие внутренних блоков в клиентском кабинете.
9. Честные данные и маркетинговые утверждения.

## Auth callback

- успех показывается только после подтверждённого backend/provider результата; ожидаемая сессия либо иной документированный verified state действительно создан;
- пустой callback, `error`, неверный или истёкший code не перенаправляются на ложный `verified=1`;
- recovery form активна только при действительном recovery context;
- внутренние технические ошибки преобразуются в понятное сообщение без секретов.

## Навигация

Допустим path-based или стабильный hash-контракт. Обязательно:

- прямая ссылка открывает нужный раздел/объект;
- reload восстанавливает его;
- Back/Forward соответствует истории;
- недоступный объект не раскрывается;
- после входа сохраняется безопасный return target.

## Критерии приёмки

- минимум семь отдельных test accounts по матрице REQ-004: A1 client, A2 client, manager A, logistician A, tenant admin A, B1 client и tenant admin B; четыре Gate-роли проверяются настоящими правами, не одним admin с view switcher;
- числа заявок совпадают во всех разделах при одинаковом scope; другой scope показывает фильтр/владельца;
- существующая заявка находится по ID;
- неизвестный ID даёт «Не найдено»;
- `/app#workflow` или его утверждённый replacement переживает reload;
- на 360/375/390 px `scrollWidth` страницы не превышает viewport;
- нет бесконечной загрузки;
- сетевой сбой показывает повтор;
- неуспешный `/auth/callback` не показывает подтверждение;
- клиент не видит dashboard менеджера, задачи сотрудников или управление ролями;
- существующие CRM, задачи, чаты и профиль не ломаются.

## Не входит

- полный редизайн;
- смена auth-провайдера;
- произвольная смена стека;
- Exchange-функции.
