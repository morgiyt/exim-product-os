# Стартовый промпт для Claude Code

Скопируйте текст ниже в Claude Code, когда Product OS и рабочий репозиторий приложения доступны разработчику.

---

Ты работаешь с двумя разными источниками:

1. `exim-product-os` — источник продуктовой истины и критериев приёмки. Код приложения сюда не добавлять.
2. Рабочий репозиторий EXIM Super App — место реализации. Не изменять его, пока не прочитаны правила и не зафиксирован baseline.

Перед первым изменением:

1. Прочитай полностью `README.md`, `AGENTS.md`, `docs/01-foundation/super-app-platform-foundation.md`, `docs/01-foundation/decisions.md`, `docs/09-decisions/open-questions.md`, `docs/06-requirements/index.md`, `docs/06-requirements/REQ-003-configurable-workflow-mvp.md`, `docs/04-pages/foundation-gate-contracts.md` и `docs/07-mvp/foundation-gate.md`.
2. Зафиксируй репозиторий, ветку, точный commit, рабочее дерево и доступные проверки рабочего приложения.
3. Сопоставь текущую реализацию с REQ-001…REQ-006 и передай короткий gap-план. Не считай наличие экрана доказательством работающего сценария.
4. Не придумывай бизнес-правила. Неопределённое помечай `TBD` и связывай с `OQ-*`.
5. Не смешивай Private Operating OS, EXIM Exchange и отдельный контейнерно-инфраструктурный продукт.
6. Не зашивай `exim.kz` как единственную компанию платформы.
7. Не называй Exchange отдельным техническим микросервисом: это пока открытое решение.
8. Не удаляй существующие данные и не сбрасывай базу. Миграции должны иметь порядок применения и отката.
9. Работай в отдельной ветке и не выполняй production deploy без отдельного подтверждения.
10. После каждого блока запускай штатную сборку и тесты. Финальная приёмка проводится на Preview минимум семью accounts по матрице REQ-004: A1 client, A2 client, manager A, logistician A, tenant admin A, B1 client и tenant admin B; используются два разных `TenantWorkspace A/B`.

Рекомендуемый текущий пакет — **Foundation Gate**. Он готов для оценки и реализации ограниченного core, но не является отдельно подтверждённым владельцем release-решением. Exchange MVP планируется следующим пакетом; механизм связи private/public не придумывать до OQ-038.
